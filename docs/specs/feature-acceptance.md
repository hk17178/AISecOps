# 功能验收清单（施工蓝图）

- 版本：v1.0
- 状态：Accepted（开发"完成"的判定权威）
- 日期：2026-06-04
- 关联：[PRD](PRD.md) · [dev-plan DoD](dev-plan.md) · [前端设计语言](../design/frontend-design-language.md)

> 本文回答一个被欠下的问题：**"功能做完"到底算什么。** 之前栽过的坑——
> 页面渲染了、接了点数据、CI 绿了，就当"完成"，结果是一堆只读页和假按钮（点了只弹提示）。
> **本文把"完成"重新钉死，并为每个功能写明"真实后端逻辑 + 可操作 + 留痕 + 配置"。**

---

## 0. 通用验收铁律（= 新 Definition of Done）

任何功能要算"完成"，**必须同时满足**：

1. **真实后端逻辑**：有真正的算法/流程在背后跑，不是写死的演示数据、不是只读展示。
2. **可操作（CRUD / 动作）**：该能增/删/改/查的要全；该能执行的动作（启用、生成、发送、审批…）真生效。
3. **关键动作有交互深度**：写/高风险动作要有**弹框**（填理由 / 二次确认），不是裸点按钮。
4. **留痕（C-23）**：所有写动作、HITL 决策写入**不可篡改审计链**（谁 / 何时 / 为什么）。
5. **持久化**：数据存得住（DB，P-18），重启不丢。内存实现只能算"未完成的过渡态"。
6. **可配置**：必要处可在 UI 配置——尤其**按功能分配大模型**（见 §4.4）。
7. **全流程能从 UI 走通**：当用户走一遍，不卡壳。
8. **诚实**：维护"真 / 示意 / 未做"状态矩阵（见 §6）；禁假按钮（见下）。

### 🚫 禁假按钮
按钮要么**真生效**，要么**明确标注"未实现 / 即将上线"并禁用**。**禁止**"点了只弹个提示、实则啥也没干"的障眼法。

### 🔗 整体可用，不做孤岛
菜单不是 17 个独立页，是**一条业务闭环**：
```
日志/告警接入 → 降噪 → 分诊 → 关联分析 → 调查 → 处置(SOAR) → 外发/通知 → 工单/HITL → 报表
                                  ↑ 资产CMDB / 威胁情报 富化 ↑      ↑ 审计贯穿全程 ↑
```
每个功能的输出要能流到下一环，不能各做各的。

## 1. 告警生命周期

### 1.1 日志/告警接入（L10/L09）—— 多源
- **真实逻辑**：支持多种来源——Syslog、Webhook（SIEM/EDR 推送）、文件、ES 查询、各厂商 API。每种来源一个**薄适配器**（ADR-0004），统一归一化（字段别名 + 严重度映射）后入告警库（L09）。
- **可操作**：在"系统设置/数据源"里增删改数据源连接、测试连通、启停。
- **配置**：每个源的连接参数（host/token）走 .env→DB（P-18，加密）。
- **验收**：☐ 至少接通 2 类源（如 Webhook + ES）☐ POST 真入库并出现在仪表盘来源分布 ☐ 数据源可在 UI 增删改测连。
- **状态**：🟡 入库管道 + 归一化已做（单一 webhook 路径）；多源适配器 + UI 管理 未做。**（日志接入按用户要求留到最后）**

### 1.2 告警降噪（L08 前置）—— 你点名的"具体怎么降噪"
- **真实逻辑**（四级，分诊前执行）：
  1. **精确去重**：对 `指纹 = hash(来源+规则+主机+关键字段)` 相同的告警合并，保留计数。
  2. **时间窗归并**：同源同类告警在滑动时间窗（如 5min）内聚合成一条（带 count）。
  3. **抑制规则**：用户维护的噪声规则（如"健康检查心跳""已知扫描器 IP""测试环境 DEV-\*"）命中即抑制。
  4. **关联聚合**：调 L08 关联引擎，把属于同一事件的多条并成一条（见 §1.5）。
- **可操作**：抑制规则**增删改查**（启用/停用）；被抑制的告警可回溯（不是丢弃，是标记）。
- **留痕**：每条告警记录"为什么被降噪/被哪条规则抑制"。
- **验收**：☑ 灌入重复/噪声告警，原始数 → 降噪后数有**真实下降**且可解释（`/api/dedupe/stats`，见 `test_dedup.py`）☑ 抑制规则可增删改且即时生效 ☑ 降噪前后可追溯（被抑制告警标记非丢弃，列在页面）。
- **状态**：🟢 **前三级已做**：L08 `DedupEngine`——①精确去重(指纹 hash 来源+主机+标题) ②时间窗归并(5min 同指纹并入计数 `bump`) ③抑制规则(主机通配/来源/关键字/IP 命中即标记抑制)。抑制规则 PG 持久化(`suppression_rules`) + `/api/suppression-rules` 增删改/启停 + 写审计(C-23)；`告警降噪`页接真(降噪率/手段拆分/规则 CRUD/被抑制可回溯)。**④关联聚合见 §1.5（下一步）**。

### 1.3 告警分诊（L07/L02）
- **真实逻辑**：Orchestrator→Triage Agent：ES 富化 + LLM 结构化研判（真威胁/误报/待研判 + 置信度 + 证据引用）；低置信 abstain（C-26）；高风险 cross-check（C-27）；真威胁自动建 HITL 工单。
- **可操作**：告警列表可**筛选/排序/批量标注**；单条可手动改判（带理由+审计）；对一条告警可一键重新分诊。
- **验收**：☐ 真威胁→建单 ☐ 可批量处理 ☐ 手动改判写审计。
- **状态**：🟢 端到端通；批量/手动改判/筛选 未做。

### 1.4 事件调查（L02）
- **真实逻辑**：Investigation Agent：查 ES 日志建时间线 + LLM 出摘要/攻击链（含引用）；可多轮追问。
- **验收**：☐ 时间线来自真日志 ☐ LLM 摘要带引用 ☐ 可追问。
- **状态**：🟢 基本通；多轮追问/导出 未做。

### 1.5 关联分析（L08）—— 你点名的"怎么用大模型出关联结论"
- **真实逻辑**：
  1. **候选关联**（规则/图）：把多条告警/事件按 **同主机 / 同源IP / 时间邻近 / 共享 IoC / Kill Chain 阶段** 关联成候选"事件簇"。
  2. **大模型出结论**：把一簇相关告警 + 上下文喂给 LLM，输出**跨告警的攻击链叙述 + 事件定性 + 影响面**（结构化 + 引用每条来源，C-24）。
  3. 高置信关联结论可升级为"安全事件"，进调查/处置。
- **可操作**：关联结果可人工确认/拆分/合并（带审计）。
- **验收**：☑ 多条相关告警 → 聚成 1 事件（L08 `correlate`，同主机/共享IP/时间邻近，见 `test_correlation.py`）☑ LLM 给出关联攻击链且**每步/每结论附引用**（C-24，离线 stub 诚实 abstain）☑ 人工确认升级为安全事件（持久化 + 审计）。
- **状态**：🟢 **已做**：L08 `correlation` 并查集聚簇（确定性，非纯 LLM，C-4）→ L02 `CorrelationAgent` 经 L05(场景 `L08/correlation`→强模型)出结构化攻击链(`attack_chain[].refs` 引用告警 id)→ L07 `CorrelationService` 编排。`/api/correlate` 出候选簇+结论；`/api/events/confirm` 人工确认建安全事件(PG `events` 持久化 + 审计 C-23)；`关联分析`页接真(运行/攻击链+引用/确认/事件列表)。🟡 待补：拆分/合并候选簇、事件状态流转。

### 1.6 威胁狩猎
- **状态**：V2 规划，空状态占位即可（已是诚实空态）。

## 2. 处置与协作

### 2.1 SOAR Playbook（L02）
- **真实逻辑**：剧本 = `触发条件 → 动作序列`（封IP/隔离/禁号）。命中触发 → **高风险动作走 HITL 工单**（C-8）→ 批准后执行（经 L06 调外部工具）→ 可撤销。
- **可操作**：剧本**增删改 + 启用/停用**；查看执行历史。
- **验收**：☐ 剧本可建/启停 ☐ 执行必经 HITL ☐ 有执行+撤销记录。
- **状态**：❌ 未做（页面剧本卡 + "启用"是假按钮）。

### 2.2 工单 & HITL（L02）
- **真实逻辑**：真威胁/高风险动作 → 建单 → **批准/驳回弹框填理由 → 写审计**。
- **验收**：☑ 弹框+理由+审计 ☐ 工单全生命周期（指派/超时/关联告警跳转）。
- **状态**：🟢 审批闭环已做（v 本轮）；指派/超时 未做。

### 2.3 外发 / 通知分发（L02）—— 通知中枢
- **真实逻辑**：渠道（企微 webhook / 钉钉 / 邮件 / 回写工单·SIEM）**配置（CRUD）** + **外发规则（命中即发，CRUD）** + 发送记录（成功/失败/重试）。
- **可操作**：渠道增删改测；规则增删改。
- **验收**：☐ 真能发一条到企微 ☐ 规则可增删改 ☐ 有发送记录。
- **状态**：❌ 未做（页面渠道/规则是写死的，"新建规则"是假按钮）。

### 2.4 Chat 助手 / 报表中心
- **Chat**：真实逻辑=NL 问答接 L02（查告警/资产/情报），答案带引用。验收：☐ 真问真答带引用。状态：🟡 UI 在，未接后端。
- **报表**：真实逻辑=按模板从真数据生成（日/周/复盘）+ 导出 MD/DOCX。验收：☐ 真生成 ☐ 可导出。状态：❌ "生成"是假按钮。

## 4. 平台

### 4.1 AI Agent（L02）—— 受限，说清楚
- **真实逻辑**：Agent 是**代码**（类 + prompt + 逻辑），**UI 不"凭空新建 agent"**。可操作的是 **Agent 配置**：启用/停用、置信度阈值、cross-check 开关、**为该 Agent 指定大模型**、编辑其 prompt。
- **验收**：☐ 改阈值/换模型/启停 即时生效 ☐ prompt 可编辑并版本化。
- **状态**：🟡 名册接真（实现/规划诚实）；配置编辑 未做。

### 4.2 MCP 工具（L06）
- **真实逻辑**：适配器列表 + 增/删/启停 + **连通测试**。
- **验收**：☐ 可测连通 ☐ 可启停。状态：🟡 列表接真；操作 未做。

### 4.3 Prompt 治理（L04）
- **真实逻辑**：Prompt 版本化（git，P-6）——**编辑 / diff / 回滚 / A-B**。
- **验收**：☐ 可编辑保存 ☐ 可回滚。状态：❌ 只读列表。

### 4.4 模型 & 成本（L05）—— 你点名的"为每个功能分配单独大模型"
- **真实逻辑**：
  1. **按场景分配模型**：L05 Gateway 支持 `场景(scenario) → provider/model` 路由表（如 分诊=便宜本地模型、调查/关联=强模型、报告=另配），在 UI 可配。
  2. 预算上限可配；真实成本/调用统计（已有）。
- **可操作**：场景→模型映射**增删改**；预算/出域开关编辑（持久化）。
- **验收**：☑ 给"分诊"和"调查"配不同模型并生效（metadata 体现不同 provider，见 `test_routing.py`）☐ 预算改了存得住。
- **状态**：🟢 **per-场景模型路由已做**：L05 `ScenarioRouter`（场景→provider，精确/前缀匹配，命中优先+降级兜底，stub 末位），多模型档位走 `LLM_PROFILES`；`/api/routing` GET/PUT/DELETE 增删改 + 路由表 PG 持久化（`llm_routes`）+ 写操作记审计（C-23）；`模型 & 成本` 页可视化编辑。🟡 待补：预算/出域开关 UI 编辑（仍 .env）。

### 4.5 系统设置（L02 平台核心）
- **真实逻辑**：配置**持久化到 DB + 密钥加密**（P-18，替换内存暂存）；**RBAC 用户管理（CRUD）**替换占位登录。
- **验收**：☐ 配置存得住 ☐ 用户可增删改 + 角色生效。
- **状态**：🟡 读+暂存内存；持久化/RBAC 未做。

## 5. 横切：持久化与审计（地基）

- **持久化（P-18）**：所有 store（告警/工单/规则/配置/资产/IoC/Prompt）从内存 → **PG**（仓储模式，CI 用内存、生产用 PG）。**没有它，上面的"可编辑"都会重启即丢 = 假完成。**
- **审计（C-23）**：所有写动作进统一不可篡改审计链；提供审计查询页。
