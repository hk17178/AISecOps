# 知识库内容设计（L03 RAG Pipeline + L04 Knowledge 蓝本）

> 状态：设计稿（蓝本）。L03 当前零代码（C-7 Reranker 缺失），本文是后续建设的依据。
> 权威架构见 [architecture-v2 §L03/§L04](../architecture-v2.md)；自用定位见 [ADR-0003](../adr/0003-self-use-positioning.md)。

## 0. 一句话

把"分析师脑子里的经验 + 散落的手册制度"变成 Triage / Investigation Agent **可检索、带出处**的外部记忆，
让 LLM 只做归纳推理、不做"知识库"（C-25），且每条结论可溯源（C-24），从根上抑制幻觉。

## 1. 核心判断：结构化走工具，非结构化才进 RAG

业界基线（Charlotte / Copilot for Security / QAX-GPT）都遵循同一条：**能精确查的别让模型"回忆"**。

| 数据 | 形态 | 归属 | 取用方式 |
|---|---|---|---|
| **CMDB 信息** | 结构化（主机/IP/属主/重要度） | L11/L12 `asset_cmdb` | **不进 RAG**。按 C-25 走 CMDB 工具直查（已实现：分诊 CMDB 富化）。嵌进向量库只会陈旧+幻觉 |
| 其余 10 类文档 | 非结构化/半结构化文本 | **L03 RAG 语料** | 切块→向量化→检索→重排，带 doc_id 引用回填 |

> 所以本文的 RAG 语料 = 你列的 11 类里**除 CMDB 外的 10 类**；CMDB 继续走 L11 工具。

## 2. 语料分层（10 类 → 3 组，按 RAG 价值与消费 Agent 排序）

### A 组 · 案例与经验（最高价值，SEC 核心，喂 Triage / Investigation）
过往"怎么判、怎么处置"的真实经验，检索增强直接给研判提供"有据可依"的先例。

| 内容 | 用途 | 主要消费方 |
|---|---|---|
| **历史告警处理记录** | 相似告警过去判真/判误 + 处置动作 → 提高分诊一致性、降误报 | Triage Agent |
| **事件处理记录** | 同类事件的调查路径、影响面、处置链 | Investigation Agent |
| **复盘总结** | 根因/改进项/教训 → 调查时避免重蹈、给建议 | Investigation / Reporter |
| **故障报告** | 已知故障特征 → 区分"安全事件"与"运维故障"，降噪 | Triage / Correlation |

### B 组 · 知识手册（参考背景，喂 Investigation 理解上下文）
理解"这台资产/这个系统正常长什么样"，让调查不离地。

| 内容 | 用途 |
|---|---|
| **应用手册** | 应用正常行为基线、端口/进程/调用关系 → 判异常 |
| **硬件手册** | 设备型号/规格/默认配置 → 判物理层异常 |
| **产品用户说明书** | 第三方产品正常用法 → 区分"误用"与"攻击" |

### C 组 · 操作与规程（喂 SOAR / Responder 出处置建议，喂合规校验）

| 内容 | 用途 |
|---|---|
| **命令库** | 排障/取证/处置 SOP 命令 → SOAR 剧本动作建议（执行仍必经 HITL，C-8） |
| **运维手册** | 标准操作流程 → 处置步骤参考 |
| **运维及监管制度** | 合规红线/审批要求 → 处置前合规校验、报告引用制度条款 |

## 3. L03 流水线（架构 v2 必备件，建设顺序）

```
原始文档 → ① 接入/解析 → ② Chunking 切块 → ③ Embedding 向量化
        → 向量库(候选: pgvector，复用现有 PG 地基) 
        → ④ Retriever 召回 Top-K → ⑤ Reranker 精排(C-7 必备★) → 注入 Agent Prompt(沙箱化 C-20)
```

- **③ Embedding**：默认走 L05 Gateway 调国产 embedding（豆包/通义，C-32 出域受控）；自用量级 pgvector 足够，不引重型向量库（零运维 P-13）。
- **⑤ Reranker（C-7 硬要求）**：召回后必过重排（cross-encoder 或 LLM rerank），缺它直接退回。这是和"玩具 RAG"的分水岭。
- **Chatbot Manager**：现有右下角 Chat 挂件接 RAG 后，从"纯 LLM 闲聊"升级为"带本地知识+出处"的助手。

## 4. 治理与安全（套用现有铁律）

- **C-24 引用**：每条检索命中回填 `doc_id / 段落锚点`，Agent 输出引用源；无出处的"具体事实"不入报告。
- **C-20 注入沙箱**：检索到的文档片段是"外部输入"，注入 Prompt 前同样要 `<<<KB_DOC>>>...<<<END>>>` 包裹，禁裸拼接（与 ES 日志同等对待）。
- **C-32 脱敏 + C-11**：含 PII/客户专有 IoC 的案例文档入库前脱敏；原始安全数据不入 git，语料库走对象存储/PG，不进仓库。
- **版本化**：文档有版本与生效时间；制度类按 `生效日期` 检索最新版，避免引用过期制度。
- **反馈飞轮衔接**：分析师在工单里"确认/否决/修正"的研判 → 沉淀回 A 组"历史处理记录"，让下一轮检索更准（架构 v2 飞轮，L01→L02 Tuning）。

## 5. 落地分期（自用节奏，不一次到位）

1. **P1 先做 A 组**：历史告警/事件处理记录入库（量大、价值最高、且已有 L09 告警库/工单可半自动沉淀）+ pgvector + Reranker，打通 Triage 检索增强闭环。
2. **P2 补 B/C 组**：手册/命令库/制度文档接入，服务 Investigation 与 SOAR 建议。
3. **P3+**：DSLM 再训练（仍按 ADR-0003 延后），KG 富化。
