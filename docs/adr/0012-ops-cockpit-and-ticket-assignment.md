# ADR-0012 · 协作驾驶舱（Ops Cockpit）+ 工单指派/进度/SLA

- 状态：已接受
- 日期：2026-06-05
- 相关：[架构补齐计划 Phase 2](../specs/architecture-gap-plan.md) · architecture-v2 §L01 · HITL Channel

## 背景

用户反馈：缺"驾驶舱"概念——管理层看不到"各个故障分配给谁、谁在处理、什么进展"，只能不断打断
技术人员问进度。现有工单只有 HITL 审批态（待审/已批准/已驳回），**没有"处理协作"维度**
（指派人、处理进度、SLA 时限、处理时间线），也没有一个一屏看清全局的只读视图。

## 决策

**新增 L01「协作驾驶舱」视图，并把工单从"审批单"扩成"协作工单"。** 守 C-15：先改本文 + V2 文字版，再编码。

### 1. 工单模型扩展（L02 工单引擎）
在现有审批字段外，增加**协作字段**（与审批态正交）：
- `assignee`：处理人（谁在处理）。
- `progress`：处理进度 —— 待处理 / 处理中 / 已完成 / 已挂起。
- `sla_due`：SLA 截止时间（按 risk 在建单时自动定：高=4h、中=24h）。
- `notes`：处理时间线（每条 {ts, author, text}），记录进展与交接。

> 审批态（status）回答"该不该做"，协作态（assignee/progress/sla）回答"做到哪了、谁在做"。两者并存。

### 2. 协作驾驶舱（L01 新视图）
只读总览（对标 SOC 值班墙）：
- **在办工单/事件**：每条显示 指派人 / 进度 / 风险 / 已耗时 / SLA 是否超时（超时标红）。
- **按处理人负载**：每人手上多少在办、多少超时。
- **汇总**：待处理 / 处理中 / 已完成 / 超 SLA 计数；待审 HITL 队列。
- 目的：**管理层一屏看清"谁在处理啥、到哪步、有没有拖"，不必逐个打扰技术。**

### 3. 跨层与纪律
- 驾驶舱是 L01 表现层视图，聚合读 L02 工单仓储（薄读，ADR-0011 允许）。
- 指派/改进度是写操作 → 经鉴权 + 审计（C-23）+ 持久化（P-18，PG 加列）。
- SLA/进度是确定性字段，不引入 LLM。

## 后果

**正面**：填上"协作可见性"空白；管理层自助看进展，减少对技术的打扰；工单成为真正的协作载体。
**负面**：工单模型变宽，PG 需加列（用 `ADD COLUMN IF NOT EXISTS` 平滑迁移）。
**风险**：SLA 规则先用固定档（高 4h/中 24h），后续可配置化。

## 备选

- **只读仪表盘扩展**：不够——驾驶舱要可指派/可更新进度，是协作面板不是统计图。
- **外接 Jira/工单系统**：违背自用"够用就行"与零运维，且 HITL 审计链要留在平台内。
