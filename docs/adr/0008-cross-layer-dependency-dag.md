# ADR-0008 · 用"显式依赖 DAG"取代"相邻层 only"，明确 L02/L07 为编排层

- 状态：Accepted
- 日期：2026-06-03
- 决策者：muzi
- 关联修订：细化 CONSTRAINTS C-13、architecture-v2 与 context/architecture 的跨层规则

## 背景

跨层调用规则有两套表述，且与架构自身的数据流冲突：

- **CONSTRAINTS C-13**："不许跨层 import / 不许反向调用 / 例外只能是 L05·L06·L12"
- **architecture-v2 与 context/architecture**：进一步收紧为 **"✅ 相邻层调用 / ❌ 跨层直连"**

但 V2 自己画的核心数据流，多处**本身就跨层**：

- `L08 算法分析 → L02 Agent 决策`：L02 与 L08 隔了 5 层，却是分诊/调查的主链路
- `L02 Agent 决策 → L07 业务出口`：L02 与 L07 也不相邻
- `L02` 要用 `L03 RAG` + `L04 模型/知识`：L02→L04 跳过 L03
- `L07` 业务能力要组合 `L02 Agent` + `L08 算法` + `L06 MCP`

根因：**L01–L12 的编号是"自上而下的概念分组"，不是"调用栈深度"。** L02（Agent 群）本质是**编排大脑**，逻辑上居中调度它所组合的能力层；L07（业务能力出口）同理是**业务编排层**。用"相邻层 only"这种空间比喻去套一个 Agent 编排的 SOC 流水线，会让真实代码"步步违规"，规则形同虚设。

## 决策

**废弃"相邻层 only"表述，改用"显式允许依赖边（DAG）"。** 规则分三类：

### 1. 横切例外（保留 C-13 原有）
任何层都可依赖：**L05 Gateway**（LLM/API）、**L06 工具适配层**（外部工具，见 [ADR-0004](0004-l06-mcp-optional-thin-adapter.md)）、**L12 核心支撑**（凭证/可观测/调度）。

### 2. 编排层例外（本 ADR 新增）
**L02（Agent 群）和 L07（业务能力）是编排层**，允许向其所组合的能力层发起非相邻调用：

| 编排层 | 允许依赖 | 用途 |
|---|---|---|
| **L02** | L03(RAG) · L04(模型/知识) · L08(分析结果) | Agent 决策需要检索、模型、算法结论 |
| **L07** | L02(Agent) · L08(分析) | 业务能力出口组合 Agent 与算法 |

> L02→L08 走"读分析结论"语义；不是 L02 反向驱动 L08 算法。

### 3. 数据面：仍禁止反向 / 禁止绕行
- **数据采集/中台层（L09/L10/L11）不得向上调用**业务/Agent 层（L01–L08）。唯一例外：**反馈飞轮**走事件驱动（L01 标注 → 事件 → L02 Tuning 消费），不算反向直连。
- 仍**禁止绕过 L05 调 LLM、绕过 L06 调外部工具**。
- 编排层例外**仅限上表枚举的边**；新增任何不在 §1/§2 列表中的跨层边，仍须写 ADR（保留 C-13 末句精神）。

### 允许依赖边（速查 DAG）

```
L01 → L02
L02 → L03, L04, L05*, L06*, L08, L12*      (* = 横切例外)
L07 → L02, L06*, L08, L05*, L12*
L08 → L09                                   (读中台数据)
L09 → L10 → L11                             (采集自下而上)
任何层 → L05*, L06*, L12*                    (横切)
反馈飞轮：L01 ──事件──▶ L02(Tuning)          (唯一合法"向上",事件驱动)
```

## 后果

**正面**：
- 规则与架构真实数据流一致，写代码不再"步步违规"。
- 把 L02/L07 的编排本质显式化，新人/未来的你一眼看懂依赖方向。
- 仍守住真正重要的隔离：数据面不反向、LLM/工具不绕行、新边要 ADR。

**负面**：
- C-13 从"一句话禁令"变成"分类列表"，理解成本略升（用速查 DAG 缓解）。
- 需同步改 3 处文档（CONSTRAINTS / architecture-v2 / context）。

**风险**：
- 编排层例外可能被滥用成"什么都能调" → 通过"仅限枚举边 + 新边须 ADR"约束；code review 由 `layer-architect` 子智能体把关。

## 备选方案

### 备选 1：维持"相邻层 only"，数据流靠 L09 事件总线中转
- 拒绝理由：L02 读 L08 分析结论强行绕经 L03–L07 中转，纯属为规则服务的样板代码，违背"够用就行"。

### 备选 2：彻底取消分层约束
- 拒绝理由：会退回 itops 那种扁平 Agent 反模式（C-5）；隔离价值（数据面不反向、LLM 必经 Gateway）必须留。
